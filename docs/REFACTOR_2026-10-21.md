# BMD converter refactor - 2026-10-21

## Findings and changes

| Finding | Result |
| --- | --- |
| Non-GUI managers silently received the background GUI palette. | Explicit single-PCX or JSON range selection; unknown GUI assignments fail before export. BMD data itself does not contain palettes. |
| GUI palette loading required all six files even when unused. | Palettes load on demand and are cached. |
| An alpha-only preview edit could replace a duplicate palette index with the lowest RGB match. | Preserve the original index when RGB is unchanged; retain full template hints for unchanged alpha-zero literals. |
| PNG import required a BMD template and fixed dimensions/anchors. | Decode exports an editable versioned JSON manifest. `build` supports new managers, new frames and edited dimensions/placement without a BMD template. Raw images are the default; preview import is explicit. |
| Active zero-sized records could not complete a PNG round trip. | Preserve their metadata in the manifest and regenerate empty rows without requiring a PNG. Unallocated metadata remains untouched. |
| Reader only checked section/range structure. Compare stopped decoding after the first difference, and rewrite could serialize malformed later streams. | Validate every active frame's type, dimensions, row bounds, controls, payload lengths and terminators during reading. Shared row traversal validates without allocating a decoded bitmap. |
| Frame-count differences reported no first differing frame. | Report the first missing frame index. |
| Forced writes could truncate existing output; export collisions could be discovered after earlier PNGs were written. | Stage BMD output and rename only after complete validation/write. Preflight all export names and palettes and create each file exclusively. |
| Raw and preview handling was embedded in converter orchestration. | Shared `BmdPngCodec`, explicit `BmdPaletteSource`, editable `BmdProject`, and smaller `BmdConverter`. Remove the unused single-type-1 example in favor of the complete manifest builder. |

The row packing algorithm and optimization candidate remain unchanged. Windows runtime layout and the historical packing audit remain the format references. The adjacent OpenVikings palette investigation established that `cr_ani_body_00.bmd` spans several animal palettes; this refactor provides explicit assignments rather than inferring a palette from the manager filename. No C++ game files were edited.

## Validation

Built `C2_BMD_to_sprites.csproj` with .NET SDK 10.0.402, configuration `ConverterAudit`, existing restored ImageSharp 3.1.12, and no native game build. Compilation succeeds with zero compiler errors; NuGet emits five existing dependency security warnings.

`tools/verify_codec.py` builds independent little-endian BMD and PNG fixtures using only the Python standard library. It verifies CLI exit codes and exact serialized output, and independently decodes generated BMD values/occupancy for edited/optimized cases. Twelve passing groups include:

- Types 0/1/2/3/4, 127/255 run boundaries, skipped runs and empty rows, signed anchors, non-ID generation order, section/manager versions and trailing bytes.
- Empty managers, unallocated records with unused metadata and active zero-sized records.
- Raw-template, raw-manifest and preview-manifest round trips, plus generation of a manager with no BMD template.
- Both optimization reuse stages, duplicate palette indices under alpha edits, occupied index-zero/alpha-zero pixels and IDs above `Int32.MaxValue`.
- Relative JSON palette paths, uncovered/overlapping ranges, missing GUI rules, and lazy GUI palette loading.
- Malformed later frames despite earlier comparison differences, unknown types, missing terminators, invalid controls/offsets/indentation, oversized frames, invalid JSON, raw occupancy errors, wrong image sizes, non-PNG content and off-palette RGB.
- Collision protection and preservation of existing outputs on failed forced builds.
- Installed 193-frame GUI BMD exported with actual GUI palettes, then rebuilt by raw manifest, preview manifest and colored-template import: all three byte-identical.

Read-only corpus verification regenerated **205/205** currently installed BMDs under the Weltwunder `data` directory, totaling **132,357,458 bytes** and **267,193 frame records**. Every `probe` reports byte identity. The 2026-10-06 audit included an extra duplicate GUI file (193 records, 937,075 bytes), explaining its 206-file total. No game resources are committed; temporary fixtures live under ignored `obj/` and are removed by the verifier.

## Limits

- Palette selection remains external and explicit. No automatic parser for game INI/CIF palette assignments or player-color transformations is introduced.
- PNG preview alpha approximates destination-dependent type-4 blending; exact blend bytes and occupancy use raw PNGs. Changing an occupied alpha-zero pixel to a skip requires raw occupancy editing.
- New artwork must already have intended frame bounds and palette colors. No implicit quantization, cropping, atlas splitting or anchor inference is applied.
- Optimized files can lose generation-order history; decoded equality does not imply byte equality with an original optimized tool output. Generator counters are regenerated; `rewrite` preserves unusual original counters.
- Export preflight prevents known collisions/data errors before output; filesystem failures can still leave partial PNG output. The manifest is created last.
- Resource limits (8192 per dimension and 16,777,216 pixels per active frame) are converter limits, not claims about the serialized format.
- The initial checkpoint retained ImageSharp 3.1.12 and emitted five NuGet warnings. This dependency was subsequently replaced; see below.

## Follow-up: remove Six Labors dependency

After an update to ImageSharp 4.1.3 introduced a blocking license check, PNG handling was migrated to StbImageSharp 2.30.16 and StbImageWriteSharp 1.16.7. Both are small C# ports of stb, without native runtime DLLs or license activation. The reader package declares `Unlicense OR MIT`; the writer's upstream README declares public domain. Links and notices are in [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

The project contains no Six Labors package reference or image types. A local `Rgba32` value and `RgbaImage` byte buffer isolate PNG I/O, keeping RGB and alpha independent. PNG dimensions and container boundaries are checked before decoding; duplicate IHDR chunks and APNG are rejected. Decoder failures are reported as CLI data errors. The BMD packing algorithm is unchanged.

The ordinary Release build succeeds with **zero warnings and zero errors**. Thirteen regression groups pass, including all previous codec checks and installed GUI byte-equal BMD round trips. Additional independent PNG fixtures cover indexed PLTE/tRNS, 16-bit channels, the Sub filter, Adam7 interlacing, APNG rejection, duplicate-header rejection and nonzero hidden RGB in an occupied alpha-zero preview pixel. Exported PNG compression can differ, while decoded data and reconstructed BMD bytes remain equal.
